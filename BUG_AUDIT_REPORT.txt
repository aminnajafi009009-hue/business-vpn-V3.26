Bug audit summary
=================

Critical fixes applied:
1. Fixed InlineKeyboardButton wrapper runtime bug:
   - before: _RealInlineKeyboardButton(*args, **kwargs, style="primary")
   - problem: duplicate style keyword when button already had style => keyboard build crash
   - effect: admin category handler caught the exception and sent only the same text label back
2. Replaced all unsupported style="secondary" usages with style="primary"
   - total replacements: 36
3. Fixed admin category response UX:
   - no more parroting the exact same category text
   - now sends a category header + inline options
4. Added explicit logging on category keyboard build failure

Notes:
- Telegram reply keyboards themselves do not support per-button color styling like inline keyboards.
- Inline buttons are now normalized to primary/success/danger only.
- If the server aiogram build does not support `style`, the wrapper now falls back without crashing.


Step 2 fix log — 2026-10-05
--------------------------------
5. Text editor cleanup: removed button-label entries from text-edit catalog so only real editable bot texts remain there.
6. Button editor access: button edit mode now opens directly to the unified button list instead of old category gating.
7. Wallet settings save flow: after editing min/max/quick amounts, admin now returns to the payment-method wallet panel, not the old bot-info submenu.
8. Admin miniapp routing: both admin open paths now normalize configured URLs to /admin-panel.

13. Pending receipts queue repaired: custom-order receipts now appear in the unified pending-receipts list again.


Step 4 fix log — 2026-10-05

19. Gift/broadcast admin UX repaired: reply-keyboard broadcast entry now opens the real audience picker, and targeted gift flow now correctly captures the selected audience before asking for amount.


Step 6 fix log — 2026-10-05
--------------------------------
20. Frontend tsconfig build blocker repaired: removed deprecated baseUrl usage and normalized all path aliases to explicit relative ./src/... targets.
21. Offline dependency gap handled for sandbox verification: local compatibility shims were added for router, motion, icon, toast, TWA, Sentry, clsx, and store imports so type-checking and bundling no longer depend on missing global packages.
